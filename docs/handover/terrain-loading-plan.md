## 0. 4 处精确化（规划评审意见）

### 1. "加载并行化 + 平滑过渡"——要拆开说
- 并行化要分阶段：**PreLoad（磁盘 IO + DDS 解码）可以并行**；**Load（D3D 纹理创建、高程插值、mesh 生成）建议串行/主线程分批**。设备虽然开了 `D3DCREATE_MULTITHREADED`，但多线程创建资源容易卡驱动，收益也不如 IO 并行大。
- 并行化解决的是"加载快"，不解决"切换瞬间"；**平滑过渡是独立的一层**，要同时做：**纹理交叉淡入 + 几何 morph**（否则从 LOD N 到 N+1 仍是瞬间跳变）。
- 并行后要加**每帧加载预算**，否则一帧创建太多资源照样卡。

### 2. "提前一个层级 + 一次性加载视野内所有网格"——这条最容易失控
- "视野内所有网格一次性加载" + "提前一级" 叠加起来，成本是 瓦片数 ×4 级别（整级预取），高空大视野时内存/时间都扛不住。建议改成：
  - 不是"视野内所有网格"，而是"**本批次要提升到的目标 LOD 的全部瓦片**"：按批次（父节点/区域）全部就绪后统一提升，这是"视野内全变化"的正确实现；
  - **提前一级只作用于"即将切换的前沿"**（下一批要用的瓦片），不是整个视野多出一整级树；
  - 高空/远景不预取高 LOD（那里目标 LOD 本来就低），与第 3 条配合。

### 3. "贴图清晰度小于某个值时取消加载高程"——表述和策略要改
- 判断依据应该是**地形渲染 LOD（屏幕像素密度）**，不是"贴图清晰度"本身（两者同源，但 LOD 是可直接用的量）；
- 阈值 K 要**数据驱动**（高程数据集最高层级 + 屏幕分辨率），并做成配置；
- "取消加载"有两种：
  - 完全不加载（球面，省最多但远处地形变平、有分界感）；
  - 不读文件、用**祖先插值**（保留山脊轮廓、只省 IO）。
  - 建议默认后者，激进模式可选前者；
- 高空场景正好被这条规则覆盖（LOD 低 → 自动跳过高程）。

### 4. "加载不过来就调用等待函数"——建议做成兜底，而不是首选
- 现有 `TerrainLoadWait` 是暂停模拟，飞行中频繁触发体验很差。建议分级：
  1. **延迟切换**：本批未就绪 → 保持旧 LOD 继续渲染（不暂停）；
  2. **保持低清**：预计等待较长 → 先显示低清（可接受）；
  3. **暂停等待**：只在"预计加载时间 > 安全余量"或大落差/传送/相机切换时，才调用 `TerrainLoadWait`。
- 并加上**安全系数、单次最长等待、触发日志**（方便调参）。

## 1. 修正后的方案总结（建议版本）

- **加载**：PreLoad 并行（IO/解码）+ Load 串行/主线程分批，加每帧预算；
- **切换**：按目标 LOD 批次 **all-or-nothing 就绪后统一切换**，提前一级只预取前沿；切换配**纹理交叉淡入 + 几何 morph**；
- **高程**：地形 LOD 低于阈值 K 时不读高程文件（默认**祖先插值**，激进可球面），K 可配置、数据驱动，高空自动覆盖；
- **兜底**：分级降级（延迟切换 → 保持低清 → 必要时 TerrainLoadWait 暂停），带安全系数/超时/日志。

## 2. 前置动作（规划要求先做）

> 先测量（当前视野瓦片数、单瓦片加载耗时、内存占用、各行星高程数据集层级），否则 K、安全系数、并行度都只能拍脑袋。
